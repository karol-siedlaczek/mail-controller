### Task 2: Audit read-authorization uses event-appropriate domain (send/delivery)

`audit_list` filters visibility by `AuditEntry.login_domain()`, which only reads the `login` field. For `send` events the relevant domain is in `sender`, for `delivery` it is in `recipient` (and `login` is typically NULL), so a domain-scoped `read_audit` holder never sees their own send/delivery events. This mirrors the (correct) metrics path in `helpers.scope_metrics` (send→sender, delivery→recipient).

**Files:**
- Modify: `mail_controller/domain/audit.py` (add `authz_domain` method, keep `login_domain`)
- Modify: `mail_controller/api/routes.py:430`
- Test: `tests/test_entities.py`

**Interfaces:**
- Consumes: `AuditEntry` frozen dataclass fields `event_type`, `login`, `sender`, `recipient`.
- Produces: `AuditEntry.authz_domain() -> str | None` — returns the read-authorization domain (send→sender host, delivery→recipient host, else login host; `None` if absent/no `@`).

```python
    def authz_domain(self) -> str | None:
        """Domain used for read-authorization: send→sender, delivery→recipient, else login."""
        if self.event_type == "send":
            addr = self.sender
        elif self.event_type == "delivery":
            addr = self.recipient
        else:
            addr = self.login
        if not addr or "@" not in addr:
            return None
        return addr.rsplit("@", 1)[1].lower()
```

### Task 4: Permission wildcard scope matches exactly one label

`Permission.allows` uses `fnmatch`, whose `*` crosses dots: scope `*.example.com` matches `a.b.example.com` (arbitrary depth) and `ex*.com` would match `ex.evil.com`. Replace `fnmatch` with explicit host-wildcard semantics: `*` = full access, exact match, or `*.base` matching exactly one label below `base`.

**Files:**
- Modify: `mail_controller/domain/permission/permission.py` (remove `import fnmatch`, rewrite `allows`)
- Test: `tests/test_permission.py`

**Interfaces:**
- Consumes: `self.scope: str`, `self.allows_action(action)`.
- Produces: `Permission.allows(domain, action)` — `*` matches all; exact scope matches identical domain; `*.base` matches `<single-label>.base` only.

In `mail_controller/domain/permission/permission.py`, delete the `import fnmatch` line and replace `allows`:

```python
    def allows(self, domain: str, action: "PermissionAction") -> bool:
        # Action gate.
        if not self.allows_action(action):
            return False
        scope = self.scope.lower()
        domain = domain.lower()
        # "*" = all; exact domain match.
        if scope == "*" or scope == domain:
            return True
        # "*.base" matches exactly one label below base (no dots in that label).
        if scope.startswith("*."):
            base = scope[2:]
            if not domain.endswith("." + base):
                return False
            label = domain[: -(len(base) + 1)]
            return bool(label) and "." not in label
        return False
```

### Task 5: Escape LIKE/ILIKE wildcards in `term` substring filters

The four list endpoints build `f"%{term}%"` and use `ILIKE` without escaping `%`, `_`, `\`. A user filter of `%` matches everything and `a_b` matches `axb`. Add a `_like_term` helper that escapes the metacharacters and an explicit `ESCAPE '\'` clause.

**Files:**
- Modify: `mail_controller/db/repository.py` (add `_like_term`; update `list_domains`, `list_users`, `list_forwardings`, `list_sender_logins`)
- Test: `tests/test_repository_sql.py`

**Interfaces:**
- Consumes: existing `term` parameter of the four `list_*` functions; `FakeCursor.executed` (list of `(sql, params)`).
- Produces: `repository._like_term(term: str) -> str` returning a `%`-wrapped, wildcard-escaped pattern; all four `ILIKE` clauses gain `ESCAPE '\'`.

```python
def _like_term(term: str) -> str:
```
